# 视觉语言与参数起点

## 范例必须实际查看

本文件提供候选链接和已记录的观察，帮助选择参考方向。进行整体设计时，必须先打开相关范例并查看真实画面；下面的文字描述不算完成查看。优先使用当前用户提供的参考，未提供时再按任务选择本文件中的链接或其他相关来源。

选择依据是当前页面的内容组织和使用任务，不是示例的标题、配色或主题。查看后先指出准备借鉴的设计方法，再形成整体方案；没有任何可见相关范例时，按 `SKILL.md` 的前置步骤处理，不根据描述自行补全。

## 默认平面化

以平面化为本 skill 的默认审美。用文字层级、对齐、留白、图片比例、纯色色块和细分隔线建立设计感。照片可以保留真实光影，界面控件与配套插画优先保持平面。

透明与磨砂玻璃是常用的局部表面表达，可以与平面布局结合。主动考虑它们对导航、浮层和面板层级的帮助；无需为了显得平面而一律去掉背景模糊。

按钮和标签不必全部采用胶囊形；图片上的浮动标签、手绘装饰和立体物件只在明确的视觉主题下使用。主图文字可置于独立文字区域，减少厚重遮罩。

## 气质与内容主题

平面化可以用于技术博客、摄影日志、研究文章或产品工具，并不决定它们的内容与情绪。先依据当前任务确定内容组织，再分别选择字体、配色与图像。既有品牌和明确参考优先。

不要把米白底、植物绿、宋体、山丘太阳插画与“慢慢生活”的文案当作个人博客的固定组合。这些元素在自然或生活主题中可以成立，换成其他主题时应重新判断；也不要一律替换成白底、紫色或黑白模板。

以下是按内容作选择的思路，不是模板清单：

- 技术与研究内容可强调标题扫描效率、分类、日期、摘要和代码的可读性，介绍区保持简短。
- 摄影日志可让真实照片承担主要表达，标题和文章信息提供清楚的阅读入口。
- 个人随笔可通过文字比例与段落节奏表达个性，是否使用衬线字与暖色取决于所需气质。

## 如何选用

- 展示页、作品集：可从摄影与编辑排版开始。
- 博客、文章归档、资讯页：先设计精选文章或列表及其信息层级，再决定是否配图和需要多大的介绍区域。
- 学习面板、创作工具：采用清晰的平面布局，可结合局部透明或磨砂面板；参考与背景适合时进一步采用完整的玻璃视觉方向。
- 社区、协作工具、信息门户：可从柔和浅色应用界面开始。

以当前用户意图、内容与已有品牌为准。这些对应关系提供选择思路，允许其他适合的组合。小范围修改延续现有方向。

## 摄影与编辑排版

已观察参考：

- [毛若昕主页](https://maorx.cn)：大幅风景摄影、中央大标题与简短说明建立首屏氛围；白色关于区域配合充足留白和少量绿色细节。
- [Untitled UI 博客](https://dribbble.com/shots/20083297-Blog-Untitled-UI)：白底、黑色大标题、宽松留白与大幅人物摄影；主文章的作者、标题、摘要和标签叠放在图片下方区域。

使用方法：

- 用一个明确的视觉主题建立识别度，协调图片与文字的面积比例。
- 通过字体比例、内容宽度和章节间距形成节奏，重要图片获得足够空间。
- 叠图文字需根据实际图片添加合适的局部遮罩或稳定文字区域，并检查窄屏裁切。
- 整屏摄影适合内容和任务允许的展示区域，不作为所有首页的固定结构。
- 内容型博客先检查读者能否尽早看到可阅读文章的标题与入口，避免大段自我宣言和装饰画占满首屏。用户明确要求品牌或介绍型首页时，按相应任务调整。

## 装饰的取舍

用真实尺寸查看页面，检查星芒、手绘线、英文副标、编号和短句是否各自有作用。相同区块不必同时配置多种装饰；统一识别性细节并允许正文区域安静下来。

判断插画是否提供当前内容的线索。如果它只是填充空间，优先调整排版或缩短介绍。检查辅助文字的字号和颜色，避免为了轻盈而让阅读信息过淡。

## 透明与磨砂玻璃

### 使用位置与层次

- 吸顶导航与悬浮工具栏：适当透出滚动内容，保持页面连续性，并与背景区分。
- 菜单、弹窗和浮动信息面板：用模糊透明表面表达覆盖关系，前景操作保持清晰。
- 图片或色彩背景上的短信息：用清透半透明或磨砂区域承载文字；复杂背景提高表面不透明度或模糊程度。
- 轻量仪表盘面板：统一一组面板的背景色、模糊与边缘处理，主次通过不同表面强度体现。

清透半透明保留更多背景细节；磨砂玻璃在半透明表面后加入背景模糊。透明与纯色表面应有不同任务，长正文和密集输入区优先保持稳定对比。背景为单一纯色时模糊的视觉收益有限，不必额外制造复杂背景来展示效果。

### 实现起点

下列数值为可调整的起点，未从参考图测量：需要稳定承载文字的表面，背景 alpha 可从 0.65–0.90、模糊半径从 12–24 px 尝试；强调通透且背景允许时，可进一步降低 alpha。按背景明暗、细节和文字对比度调整，浅色与深色表面分别选择合适的色值。

下面是浅色面板的基础示例。基础表面可独立阅读，在支持背景模糊时再增加通透效果；项目应将颜色、边框和模糊参数统一为设计变量。

```css
.glass-surface {
  --glass-tint: rgb(255 255 255 / 0.78);
  --glass-blur: 16px;
  background: #f8f9fc;
  border: 1px solid #dfe3eb;
}

@supports ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass-surface {
    background: var(--glass-tint);
    -webkit-backdrop-filter: blur(var(--glass-blur));
    backdrop-filter: blur(var(--glass-blur));
  }
}
```

背景模糊作用于元素背后的内容，表面需透明或半透明才能看见效果，见 [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)。整个元素的 `opacity` 会影响前景内容，参见 [MDN opacity](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/opacity)；应优先调整背景色的 alpha，保持文字与控件清晰。

### 独立悬浮表面与透明度层级

先区分参数的含义。`rgb(255 255 255 / 0.35)` 表示白色底层有 35% 不透明度、65% 透明度；提高通透感应降低 alpha。模糊强度独立调节，不用提高模糊来替代降低不透明度。

对于“导航磨砂、搜索框独立悬浮”的需求，将定位容器与材质层分开：

- 顶层定位容器保持透明；导航行和搜索框各自拥有背景模糊表面。若使用伪元素绘制导航底层，尺寸只覆盖导航行，并禁用该装饰层的指针事件。
- 吸顶或固定定位让内容能实际滚到后面；同时处理层级、侧栏偏移与窄屏菜单的位置，防止导航遮住控件或让打开的菜单留在视口外。
- 搜索框自身可以更不透明，四周的间距保持透明。检查父容器和伪元素是否仍绘制了整行底色或模糊带；控件半透明并不代表周围无遮挡。
- 桌面横排变成手机双行时，重新检查表面覆盖范围。导航底层不能因容器总高度增长而自动包住下一行搜索框。
- 合并重复声明与页面特有覆盖，使桌面、手机和不同主题中的不透明度都来自明确的共享变量。背景模糊不可用时保留可读的纯色回退。

以下记录来自一次已实现的社区页面迭代，仅说明参数之间的关系，不作为其他项目的默认主题：

| 项目 | 当次结果与用途 |
| --- | --- |
| 页面底色 | 用户指定纯白 `#fff`，开放内容流共用背景 |
| 导航底层 | 白色 alpha `0.35`，透出后方内容 |
| 搜索框底层 | 白色 alpha `0.65`，比导航更不透明 |
| 磨砂 | `blur(18px) saturate(140%)`，前景文字保持清晰 |
| 搜索框闲置尺寸 | 完整尺寸的 `0.86`，悬停或输入恢复 `1` |
| 动画时长 | 下拉菜单按用户要求使用 `0.5s`，搜索缩放沿用相同节奏 |

该页面使用的紫色、社区文案与西瓜图形属于项目内容，不随这些规则迁移。

### 视觉验证

检查亮色、暗色和细节较多的背景，以及滚动内容经过面板时的表现。不要仅通过静态纯色背景判断可读性。避免嵌套多层模糊和持续动画化模糊半径，检查手机上的滚动与交互；必要时缩小效果区域或提高表面不透明度。

### 深色玻璃参考

已观察参考：

- [Que 课程面板](https://dribbble.com/shots/26740440-Que-Course-Portal-Glass-Effect-Dashboard)：深色背景、半透明面板、大圆角、细亮边和柔和背景光晕；统计、课程、日程和活动按栅格分组，荧光绿、青色和黄色用于进度与状态。

使用方法：

- 先建立清晰的模块与对齐关系，再添加材质层次。
- 统一表面透明程度、亮边强弱、阴影与背景光晕的使用规律。
- 亮色在状态、数据重点与主要操作上集中出现，重要文字保持清晰对比。
- 玻璃表面随内容复杂程度提高稳定性；模糊效果不可用时仍保持可读。

## 柔和浅色应用界面

已观察参考：

- [大学社区](https://dribbble.com/shots/15385888-Forum-dedicated-to-University-Community)：顶部导航、左侧课程导航、中央讨论流与右侧成员信息；白色内容卡片、浅色背景、柔和阴影，紫色强调主要操作与选中状态，淡色标签辅助分类。

使用方法：

- 多栏承载明确的不同任务，主内容在面积和对比上占据主导。
- 控制边框和阴影的强度，用表面差异和空间关系区分区域。
- 选中状态可由底色、短线或图标共同表达，按钮与标签保持不同的视觉权重。
- 移动端按任务优先级重排，辅助信息可进入详情或可展开区域。

## 搜索框缩放与下拉动画

仅在需求需要时使用这类交互；不将动态缩放添加到所有搜索框。

### 搜索框状态

- 闲置为紧凑状态，支持悬停的设备在 hover 时展开；输入框获得焦点后持续展开，移开鼠标也不收起。触屏通过点击或聚焦展开，键盘通过 Tab 进入。
- 展开终点复用用户已确认的完整尺寸。只需视觉缩放时可使用 `transform: scale()`，保持布局占位不变；若会导致文字过小或点击区域不足，则调整容器尺寸、内边距或内部排版。
- 对 hover 使用 `@media (hover: hover)`，对输入使用 `:focus-within`。两种状态需分别验证；测试聚焦成功不能证明鼠标悬停也成功。
- 仅动画化需要变化的属性，沿用用户指定的时长与页面节奏；提供 `prefers-reduced-motion` 下的即时状态切换。

### 下拉菜单状态

- 简单状态可使用 CSS；用户明确要求 JavaScript、需要动态高度或中断衔接时，可使用 Web Animations API。`0.5s` 在 JavaScript 中对应 `duration: 500` 毫秒，不作为通用默认时长。
- 展开前先让内容可测量，根据实际高度设定终点；若动画涉及容器的 padding 和 margin，同步处理这些间距，防止关闭末尾跳动。
- 收起动画结束后再隐藏容器或移除内容。关闭期间及时禁用菜单内部交互，桌面切换后恢复正常导航；不要仅为了动画留下可 Tab 进入的隐藏链接。
- 用户反向点击时，读取当前视觉状态后取消旧动画，从当前帧过渡到新目标。结束和卸载时清理动画、临时 overflow 和媒体查询监听，避免高度锁死或残留裁切。
- 检查首次加载不自动播放关闭动画、连续点击后最终状态正确，以及窗口跨断点后菜单和导航仍能使用。

## 参数起点

以下为可调整的建议，未从参考图测量。优先沿用已有设计变量；新项目按实际画面调整并保持一致。

| 项目 | 建议起点 |
| --- | --- |
| 间距序列 | 4、8、12、16、24、32、48、64、96 px |
| 中文正文 | 16 px，行高 1.6–1.8；密集应用可采用 14 px |
| 标题 | 建立 3–4 个有区分的层级，展示标题按内容与视口调整 |
| 中文长正文 | 以约 30–40 个汉字一行为检查起点 |
| 圆角 | 平面方向以 0–6 px 为起点；胶囊形或更大圆角按项目需求选择 |
| 移动端页面边距 | 16–24 px；桌面按内容宽度与栅格确定 |

颜色、透明度、模糊程度和阴影强度根据实际背景与对比度决定。避免把某个示例的颜色或面板数量当成所有项目的固定要求。
