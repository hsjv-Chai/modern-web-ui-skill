# 现代网页 UI 设计

将“结构清晰、空间舒展、层次细腻、有辨识度”落实为可执行的网页设计选择。默认采用平面化的现代视觉，通过排版、比例、色块和细线建立层级，并在合适位置主动运用透明与磨砂玻璃增强通透感。支持不同项目的视觉表达，具体品牌、主题与技术栈由当前项目决定。

## 使用上下文决定方向

- 先查看当前页面、设计变量、组件和项目约束。用户明确的风格与参考优先；在既有界面中延续成熟的设计语言，按请求范围改进。
- 沿用项目技术栈与组件体系。视觉改进本身不构成迁移框架、更换组件库或添加大型依赖的理由。
- 根据页面任务区分展示、阅读和操作区域，确定主内容、主要操作与信息密度。
- 用户提供参考时按下方前置步骤查看实际画面，不从页面标题或文字推断未看到的字体、材质、动画或移动端行为。
- 缺少关键业务信息时提一个聚焦问题；其余设计选择根据项目作合理判断并继续。
- 用户要求逐步调整时，每轮聚焦当前修改，保留已接受的布局、材质和交互。明确的局部修改无需重新制定整页方案或重复外部范例流程。

## 整体设计前必须查看范例

此步骤适用于新站或新页面的整体设计、整体视觉方案制定、整页重设计，以及跨页面的大范围风格调整。修改局部间距、单个组件状态或修复功能时，按实际需要查看，无需重新执行整个流程。

- **在确定整体风格、布局或开始整体视觉实现之前，必须先实际查看与本次任务相关的范例。** 在此之前可以梳理需求和检查项目，不能仅凭惯用模板开始整体设计。
- 优先查看用户提供的相关范例。用户未提供时，从 [references/design-language.md](references/design-language.md) 的链接中选择适合的范例，或寻找更符合当前任务的公开参考，并实际打开查看。
- 网站通过浏览器或 Computer Use 查看真实渲染画面；图片范例直接查看图片。本地图片使用可用的图片查看工具。阅读链接、搜索摘要、网页正文或本 skill 的文字分析，都不能替代查看画面。
- 查看后简要说明实际观察到的布局、字体层级、色彩、组件和装饰，以及本次准备借鉴的部分，再继续设计。静态图不作为动效或响应式行为的验证依据。
- 范例加载失败时，尝试可用的其他查看方式或相关范例；如果仍没有任何可见的相关范例，应说明具体阻塞并请求可访问的链接或图片。此时继续处理不依赖视觉的需求与项目检查，暂停整体视觉方案与实现，不自行跳过此步骤。
- 同一任务中已实际查看、仍与当前方向相关的范例可以复用观察结果；不能把其他对话中的文字总结视为本次已查看的证据。

## 选择视觉语言

完成上述范例查看后，新建视觉方向或需要选取参数时，阅读 [references/design-language.md](references/design-language.md)。局部调整只读取相关部分。

根据内容选择平面图文、纯排版或轻量应用界面。将透明与磨砂玻璃纳入常用设计手段，主动评估它们在导航、浮层和轻量面板中的使用；结合已查看范例、背景和层级需要决定具体位置。平面布局可配合局部玻璃效果，整体立体造型与实体拟真材质仍按明确的风格选择使用。参考路径可以扩展，每个项目保持一种主要语言。

在实现前简述最重要的设计选择，例如布局、标题比例、主色和材质。已有规范足够明确的局部调整可直接沿用，无需为每个小改动另写方案；整体设计仍须完成范例查看。

### 分别确定内容主题与视觉气质

- 内容主题来自当前任务、真实内容与品牌。不要仅因“个人博客”就填入慢生活、自然、旅行或成长叙事；需要示例内容时，依据已知主题编写，主题未知则使用中性的内容示例。
- 平面化约束表面与层次的表达，不预设田园、文艺、日系或其他气质。米白底、鼠尾草绿、宋体标题、植物与山丘插画可以按主题选用，不作为默认整套搭配，也不固定换成另一套颜色与字体模板。
- 字体、色彩与图像各自应有内容、品牌或参考依据。缺乏方向时，从清晰的无衬线排版、中性色和少量功能性强调色开始，再加入项目特征。
- 提取参考中的比例、层级与组织方法。单个参考的风景、配色或文案主题不自动迁移到所有项目。

## 将审美落实到界面

### 结构与排版

- 让主要内容获得适当的空间和视觉权重，辅助内容通过位置、间距、字号或色彩降低权重。
- 卡片承载独立的信息组。根据内容使用开放排版、列表、分隔线、表格和图文组合，保持页面节奏。
- 用户要求开放、无边界感时，检查独立底色、边框、圆角、阴影、容器内缩和侧栏竖线，改用共享页面背景、对齐、留白与必要的轻分隔线。按屏幕释放布局宽度，同时保留适合长文阅读的行宽；不把所有控件的边界一并删除。
- 用对齐关系、标题比例和组间距离建立秩序。同级元素共享样式；内容组内距离小于组间距离。
- 根据任务调整密度。展示区域可以舒展；表格、表单与高频工具区域保留操作效率。
- 博客、文章归档和资讯首页优先让读者找到可阅读的内容，默认从简短介绍与精选文章或列表组织首屏。检查标题与装饰插画是否把首篇文章入口推得过远；只有介绍、品牌展示本身是主要任务时，才使用占据大部分首屏的宣言式 Hero。
- 英文参考转为中文时重新检查字体、行高、断行和文本长度，保留真实内容的可读性。

### 色彩、材质与图像

- 使用纯色、透明与磨砂表面形成有区别的层次，保持轻量边框和协调的圆角。先通过排版与留白区分主次，再以透明和背景模糊表达覆盖关系与通透感。
- 默认配图采用摄影、平面插画或抽象图形。拟真书本、咖啡静物、倾斜物体、纸张厚度、模拟光照与投影会引入实体感，使用前需符合用户选择的方向。
- 中性色承载基础文字和表面，强调色表达品牌、操作或状态；辅助色保持稳定含义。
- 将背景氛围、容器表面、内容信息的层次区分清楚。阴影表达浮起关系，边框表达边界。
- 长正文、表格和密集表单保留稳定的内容表面，透明与磨砂效果集中用于适合透出背景的区域。
- 在图片、渐变、透明表面和不同主题上分别检查文字可读性。背景或材质缺失时仍保持基本层级。
- 图片应匹配内容、色调和裁切焦点。只使用可用或可明确获取的资源；缺少素材时给出可用的布局与替代方案。
- 图标保持一致的风格和视觉重量，含义不明确的操作配合文字标签。

### 透明与磨砂玻璃

- 在吸顶导航、悬浮工具栏、菜单、弹窗面板、图片叠层和轻量信息面板中主动考虑透明或磨砂效果，使其承担层级、背景关联或空间连续性的作用。
- 根据背景区分清透半透明与磨砂玻璃。背景内容简单且文字清晰时可仅半透明；背景细节干扰阅读时使用带背景色的模糊透明面板。参考中的玻璃方向可用于浅色或深色界面。
- 用带 alpha 的背景色控制表面透明度，保持文字、图标与控件清晰；使用 `backdrop-filter` 模糊面板背后的内容，不用整个容器的 `opacity` 或 `filter: blur()` 把前景一起变淡或模糊。实现起点见 [references/design-language.md](references/design-language.md) 的“透明与磨砂玻璃”。
- 根据实际背景协调背景色、透明度、模糊半径与细边框，检查滚动前后和不同图片区域的可读性。玻璃效果无需附带厚重高光、立体倒角或物体投影。
- 明确区分透明度与不透明度：背景 alpha 越小越通透。用户要求“更透明”时降低 alpha；报告百分比时说明是不透明度，避免把调整方向说反。
- 导航、搜索框与外层容器分别控制表面。需要搜索框独立悬浮时，四周保持透明，只在搜索框自身添加底色、模糊与轻阴影；移动端换行后不要让导航的整条磨砂层延伸到搜索框四周。搜索框可比导航更不透明以稳定输入对比度。具体做法见 [references/design-language.md](references/design-language.md) 的“独立悬浮表面与透明度层级”。
- 避免多层玻璃和全屏高强度模糊堆叠；在移动端检查滚动与交互。模糊不可用或影响阅读时，使用更实的表面颜色，保留清晰的分层。

### 让装饰服从内容

- 装饰应承担品牌识别、构图或信息表达的作用。避免在每个区块重复叠加星芒、手绘下划线、无信息作用的英文小字、编号和标语；保留少量有依据的视觉细节即可。
- 插画应与文章或产品主题相关。没有适合的素材时，可以采用纯排版，不为填满留白添加通用风景插画。
- 留白与文字灰度以真实阅读效果为准。避免同时使用过浅的颜色和过小的字号，让摘要、日期与导航难以辨认。

### 实现与交互

- 将重复使用的颜色、字体、间距、圆角和阴影落实为项目共享变量，优先复用已有变量。
- 重复组件共享结构与状态；根据业务需要覆盖悬停、键盘焦点、选中、禁用，以及加载、空白和错误状态。
- 用内容决定响应式重排。多栏页面在窄屏明确导航与辅助信息的去向，主要操作可访问，正文和控件不被裁切。
- 动效用于表达状态、反馈和层级变化，保持一致节奏并尊重减少动态效果的系统偏好。静态参考图不视为已验证的动效示例。
- 展开动画覆盖打开与收起；收起完成前保持元素可渲染，快速切换时从当前帧衔接，并在结束、卸载或切换断点后清理临时样式。用户指定 JavaScript 动画时可用 Web Animations API，按指定时长执行。
- 搜索框的紧凑状态同时响应可悬停设备的 hover 与键盘、触屏的 focus-within；输入期间保持展开，恢复到已确认的完整尺寸，避免推动周围内容。检查缩小后的文字和点击区域，不能只实现鼠标悬停。细节见参考文件的“搜索框缩放与下拉动画”。

## 验证和交付

实现页面时，用可用浏览器查看实际画面，覆盖有代表性的桌面和移动宽度，检查对齐、留白、中文断行、内容溢出、主要操作与适用的键盘交互。无法运行或查看时，明确尚未完成的视觉验证。

对于玻璃、悬浮与缩放修改，实际滚动正文和图片经过控件后方，检查周围是否仍被父容器遮挡；分别操作闲置、悬停、输入与离开状态。计算样式可核对参数，不能替代真实画面与交互验证。

交付前检查视觉气质是否有当前任务的依据、装饰是否重复、主要内容是否足够早出现。若成品仍像可随意替换标题的通用模板，优先调整内容组织、比例和字体关系，再决定是否需要增加装饰。

针对需求运行项目已有的相关检查。纯文案或轻微样式调整以相应的视觉检查为主；交互或逻辑变化补充必要验证。

按任务交付可工作的页面、具体的修改或可执行的设计规范，并简要说明设计选择、验证结果与剩余限制。编写规范时明确哪些是要求、哪些是建议起点，给出可检查的条款。
